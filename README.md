# Photobooth สำหรับงาน The Last Take in Sci-lywood

ระบบนี้ใช้ Photobooth-App v9 เป็นตัวควบคุมกล้องและการประมวลผล พร้อมหน้าคีออสก์ภาษาไทยสำหรับกล้อง Canon, เทมเพลต 1–6 ช่อง, QR download, AirDrop/Web Share และพิมพ์ผ่าน CUPS

## เว็บสาธารณะและส่วนที่อยู่บน Mac

หน้าเว็บข้อมูลกิจกรรมสำหรับ Vercel อยู่ใน [`vercel_public/`](vercel_public/) และไม่มี API ควบคุมอุปกรณ์ ให้กำหนด Root Directory ของ Vercel เป็น `vercel_public` เท่านั้น ส่วนหน้าถ่าย หน้าควบคุม โต๊ะพิมพ์ จอคิว กล้อง Canon และเครื่องพิมพ์ยังต้องรันบน Mac ผ่าน `npm run dev` อย่า deploy โฟลเดอร์หลักของโปรเจกต์ เพราะมีโค้ดควบคุมเครื่องและข้อมูลในเครื่อง

ภาพสำเร็จรูปที่สร้างใหม่จะอัปโหลดฉบับดาวน์โหลดไปยัง Vercel Blob แบบ private อัตโนมัติเมื่อ `vercel_public/.env.local` มี `BLOB_READ_WRITE_TOKEN` และ Mac ต่ออินเทอร์เน็ต ภาพเก่าอัปโหลดได้เมื่อเจ้าหน้าที่เปิดภาพในแกลเลอรีแล้วกด “สร้าง QR ออนไลน์” เท่านั้น QR ใช้ได้ทุกเครือข่ายเป็นเวลา 1 ชั่วโมงนับจากอัปโหลด เมื่อหมดอายุเจ้าหน้าที่กดสร้าง QR ใหม่ให้ภาพเดิมได้ ไฟล์ต้นฉบับยังอยู่ใน Mac และการพิมพ์ไม่เปลี่ยนแปลง หากอัปโหลดล้มเหลว ระบบลองใหม่ขณะเปิดหน้าภาพ และไม่แสดง QR ออนไลน์ปลอม ไฟล์บน Blob ถูกลบด้วยงานรายวันหลังหมดอายุ; การเข้าถึงถูกปิดทันทีเมื่อครบ 1 ชั่วโมง

## เริ่มใช้งาน

1. ต่อกล้อง Canon ที่ `libgphoto2` รองรับเข้ากับ Mac ด้วยสาย USB ที่รองรับข้อมูล เปิดกล้อง และปิดแอปอื่นที่กำลังจับกล้องอยู่
2. ต่อเครื่องพิมพ์ที่ติดตั้งใน macOS/CUPS และตรวจว่า macOS มองเห็นเครื่องพิมพ์
3. เปิด Terminal ที่โฟลเดอร์นี้แล้วรัน:

   ```bash
   npm start
   ```

4. เปิด [http://localhost:8000](http://localhost:8000) บนจอที่ให้ผู้ถ่ายดูภาพ และเปิด [http://localhost:8000/?view=operator](http://localhost:8000/?view=operator) อีกหน้าต่างหนึ่งบนจอ Mac

หากเริ่มจากจอถ่าย ให้กด **เปิดจอควบคุม** ที่มุมล่างซ้าย แล้วลากหน้าต่างจอถ่ายไปจอแยกและเปิดเต็มจอ ส่วนหน้าควบคุมบน Mac มีพรีวิวเล็กด้านซ้ายพร้อมปุ่มยืนยัน/ถ่ายใหม่ และมีภาพที่ถ่ายเสร็จแล้วด้านขวาสำหรับจัดเทมเพลต พิมพ์ แชร์ AirDrop ดู QR และตรวจคิวพิมพ์ การเปิดแกลเลอรีหรือหน้าจัดเทมเพลตบน Mac ไม่เปลี่ยนหน้าพรีวิวของผู้ถ่าย

### คิวผู้เข้าถ่ายและจอที่สาม

บนจอควบคุม เจ้าหน้าที่เลือกประเภทคิว (เริ่มต้น SCI) และกรอก **จำนวนคน** ก่อนกด **+ ออกบัตรคิว** ระบบแสดงตั๋วทันทีให้ผู้ใช้ถ่ายหน้าจอเก็บไว้ เจ้าหน้าที่กด **บันทึก PNG** หรือ **แชร์ / AirDrop** เพื่อส่งไฟล์ตั๋วได้ และเปิดตั๋วอีกครั้งจากรายการคิวได้ การออกคิวทำโดยเจ้าหน้าที่เท่านั้น ไม่มีหน้าจองเองบนมือถือ

เมื่อถึงคิว ให้กด **เริ่มถ่าย** ที่หมายเลขนั้น แล้วให้ผู้ใช้เลือกกรอบบน iPad ที่อยู่ใน Wi-Fi เดียวกับ Mac โดยสแกน QR ในแผงคิวหรือเปิด `/template-chooser.html` หน้า iPad แสดงเฉพาะ **คิวที่กำลังถ่าย** ไม่แสดงคิวรอ และเลือก/เปลี่ยนกรอบได้ก่อนกดชัตเตอร์แรกเท่านั้น จากนั้นภาพชุดและภาพที่ประกอบเทมเพลตจะผูกกับหมายเลขคิว โดยเห็นเลขคิวในแกลเลอรีและงานพิมพ์ ภาพเก่าที่ไม่ได้ผูกคิวจะแสดงว่าไม่พบเลขคิว

กด **จัดการคิว/สถิติ** เพื่อเพิ่มประเภท เช่น `SMO` และดูจำนวนคิว/ผู้มาใช้แยกประเภทและรอบงาน จำนวนผู้มาใช้คำนวณจากจำนวนคนที่กรอกสำหรับคิวที่มีภาพแล้วเท่านั้น เมื่อจบรอบสามารถตั้งชื่อรอบใหม่เพื่อเริ่มเลขแต่ละประเภทที่ `01` โดยประวัติรอบเก่าจะยังอยู่ ระบบไม่ยอมเปิดรอบใหม่ถ้ายังมีคิวรอถ่าย กำลังถ่าย หรืองานพิมพ์ค้าง

กด **เปิดจอคิว** แล้วลากหน้าต่างไปจอที่สาม (หรือเปิด `http://localhost:8000/queue-board.html` โดยตรง) จอนี้แสดงคิวที่กำลังถ่าย งานที่รอ/กำลังพิมพ์ และงานที่ CUPS แจ้งว่าพิมพ์เสร็จ เมื่อสั่งพิมพ์จากจอควบคุม ระบบจะเปิดจอคิวให้อัตโนมัติหากยังไม่เปิดอยู่ สถานะ “พิมพ์เสร็จ” อิงจาก CUPS; ควรตรวจแผ่นกระดาษจริงก่อนส่งให้ผู้เข้าร่วม

`run.sh` จะหยุด `ptpcamerad` ชั่วคราวเพื่อให้ gphoto2 จับกล้องได้ และเปิดกลับให้อัตโนมัติเมื่อปิดระบบ นอกจากนี้จะติดตั้งไฟล์ปรับแต่งจาก `photobooth_custom/` เข้า virtual environment ทุกครั้ง จึงไม่ต้องแก้ไฟล์ใน `venv/` โดยตรง

## ขั้นตอนหน้างาน

- ภาพ Live View จากกล้องแสดงเต็มจอ หากไม่พบสัญญาณ ระบบจะแสดงคำแนะนำแทนการแจ้งว่า “พร้อม”
- เจ้าหน้าที่กดเริ่มคิวก่อน แล้วให้ผู้ใช้เลือกกรอบบน iPad **ก่อนกดชัตเตอร์แรก** จำนวนช่องของกรอบจะเป็นจำนวนรูปที่ระบบถ่ายจริง เช่น กรอบ 1 ช่องถ่าย 1 รูป และกรอบ 6 ช่องถ่าย 6 รูป
- กดชัตเตอร์ที่ตัวกล้อง ระบบรับภาพทันทีและให้ตรวจ/ถ่ายใหม่ทีละภาพจนครบตามจำนวนช่อง
- หลังถ่ายครบ เลือก **จัดเทมเพลต** เพื่อสลับภาพไปยังตำแหน่งใดก็ได้ แล้วแก้ชื่อหลักและข้อความรอง
- กด **สร้างภาพพร้อม QR** เพื่อบันทึกภาพสำเร็จรูปเข้าคลัง สแกน QR เพื่อดาวน์โหลด หรือสั่งพิมพ์/แชร์จากหน้าจอได้ทันที
- ยืนยันหรือถ่ายใหม่ได้จากทั้งจอถ่ายและหน้าควบคุม โดยคำสั่งผูกกับภาพปัจจุบันเพื่อกันการกดซ้ำข้ามหน้าต่าง

ปุ่ม **ตั้งค่าอุปกรณ์** ใช้ตรวจสถานะกล้อง Canon, สร้าง/แก้เทมเพลต และจัดการโปรไฟล์เครื่องพิมพ์ได้ โดยตัวแก้ไขเทมเพลตรองรับ:

- 1–6 ช่องภาพ พร้อมลากย้ายช่องและกำหนด X, Y, ความกว้าง และความสูง
- ผ้าใบขนาด 600×900 ถึง 2400×3600 พิกเซล
- ภาพพื้นหลัง PNG/JPG และกรอบซ้อนหน้า PNG โปร่งใส
- เทมเพลตมาตรฐานภาพเดี่ยว, 3 ช่อง และ 6 ช่อง

ในแท็บ **เทมเพลต** กด **ทำสำเนาเพื่อแก้** สำหรับกรอบมาตรฐาน (กรอบต้นฉบับจะยังอยู่) หรือกด **แก้ไข** สำหรับกรอบที่สร้างเอง เปลี่ยนชื่อ จำนวนช่อง ตำแหน่ง ขนาดกระดาษ และเปลี่ยน/นำภาพพื้นหลังหรือภาพซ้อนหน้าออกได้ กรอบที่สร้างเองกด **ลบ** เพื่อลบรายการและไฟล์กรอบที่อัปโหลด โดยไม่ลบภาพถ่ายที่สร้างแล้ว ส่วนกรอบมาตรฐานกด **ซ่อน** แล้วนำกลับมาได้ในหัวข้อ “กรอบมาตรฐานที่ซ่อนไว้” ระบบไม่อนุญาตให้แก้หรือลบกรอบที่คิวกำลังใช้อยู่

ภาพใหม่ที่อัปโหลดสำเร็จใช้ QR ออนไลน์ได้ทุกเครือข่าย 1 ชั่วโมง ภาพเก่ากดสร้าง QR ออนไลน์ได้จากแกลเลอรี หากไม่ได้ตั้งค่า Blob ยังดาวน์โหลดผ่าน Mac ได้ทางปุ่มเปิดหน้าดาวน์โหลด (ต้องอยู่ Wi-Fi เดียวกันและไฟร์วอลล์อนุญาตพอร์ต `8000`)

แกลเลอรีแยกภาพเก่าตามวันที่โดยอัตโนมัติ กด **+ โฟลเดอร์โครงการ** เพื่อสร้างโครงการและตั้งเป็นโครงการของภาพถัดไป หรือย้ายภาพทั้งชุดจากหน้ารายละเอียดไปยังโครงการอื่น การลบโฟลเดอร์ต้องทำจาก `localhost` บน Mac เครื่องหลัก ระบบจะแสดงจำนวนภาพและให้พิมพ์ชื่อโฟลเดอร์ยืนยันก่อนลบรูปจริง ภาพออนไลน์ที่เกี่ยวข้องจะถูกลบด้วยหากมี และไฟล์สำรองเพื่อกู้คืนจะอยู่ใน `recycle/photobooth-folders/` บน Mac (ควรล้างเองภายหลังเมื่อแน่ใจว่าไม่ต้องกู้คืน)

## กล้องและเครื่องพิมพ์

- กล้อง: Canon ที่ `libgphoto2` ตรวจพบ (ครั้งละหนึ่งตัว)
- Camera backend: `Gphoto2` (USB tethering, Live View และชัตเตอร์บนตัวกล้อง)
- เครื่องพิมพ์: คิวใดก็ได้ที่ติดตั้งใน macOS/CUPS
- โปรไฟล์กระดาษ: 4×6 นิ้วไร้ขอบ, 6×8 นิ้ว และ A4 พร้อมปุ่ม **Test Print**
- ทุกครั้งที่กดพิมพ์จากแกลเลอรีหรือโต๊ะพิมพ์ ระบบให้เลือกโปรไฟล์เครื่องพิมพ์ก่อนส่งงาน งานหนึ่งครั้งไปเครื่องเดียว; สามารถกระจายงานหลายภาพไปคนละเครื่องและให้ CUPS พิมพ์พร้อมกันได้
- เครื่องที่ CUPS แจ้งว่าไม่พร้อมจะเลือกส่งงานไม่ได้ คิวพิมพ์แสดงสถานะและงานค้างแยกตามเครื่อง อย่ากดส่งซ้ำทันทีหากคำขอขัดข้อง ให้ตรวจคิวก่อนเพื่อป้องกันรูปซ้ำ
- ตรวจว่าทั้งสองเครื่องใส่กระดาษ 4×6 ถูกด้าน ใช้ขนาด/โหมดไร้ขอบตรงกับโปรไฟล์ และพิมพ์ทดสอบทีละเครื่องก่อนเริ่มงานจริง; สถานะ CUPS ว่าเสร็จแล้วไม่ยืนยันว่าแผ่นพิมพ์ออกมาถูกต้อง
- ค่าหลักทั้งหมดอยู่ที่ [`config/config.json`](config/config.json)

เทมเพลตที่สร้างและโปรไฟล์เครื่องพิมพ์จะเก็บใน `userdata/photobooth_templates/` และ `userdata/photobooth_printers.json` ตามลำดับ

ก่อนวันงานควรทดลองถ่ายและพิมพ์จริงอย่างน้อยหนึ่งชุด เพราะชื่อคิว CUPS และโหมด USB ของกล้องอาจต่างกันในแต่ละเครื่อง

## การแชร์บน Mac

- AirDrop: ระบบเปิด AirDrop/Finder และเลือกไฟล์ให้บน Mac
- iPhone/iPad/Android: ใช้ QR download และ Web Share ของเบราว์เซอร์
- Google Quick Share ไม่มีไคลเอนต์ทางการสำหรับ macOS จึงใช้ Web Share/QR เป็นทางเลือกที่ทำงานข้ามอุปกรณ์และเสถียรกว่าสำหรับหน้างาน

## โครงสร้างไฟล์ที่ควรแก้

```text
Photobooth-app/
├── config/config.json
├── photobooth_custom/
│   ├── backend/share.py
│   └── frontend/
│       ├── index.html
│       └── assets/
├── scripts/
│   ├── install_customizations.sh
│   └── qr-svg.mjs
├── run.sh
└── README.md
```

ไฟล์ภาพ, ฐานข้อมูล, cache, log และ `venv/` ถูกตัดออกจาก Git เพื่อไม่ให้ข้อมูลลูกค้าและไฟล์ขนาดใหญ่หลุดเข้า repository

## ความปลอดภัยก่อนเปิดใช้งานจริง

รหัส Admin เริ่มต้นใน `config/config.json` ยังเป็น `0000` เพื่อไม่ให้ผู้ดูแลถูกล็อกออกจากระบบระหว่างพัฒนา ต้องเปลี่ยนเป็นรหัสที่เดายากก่อนเชื่อม Mac เข้ากับเครือข่ายของงาน และไม่ควรเปิดพอร์ต `8000` ออกสู่อินเทอร์เน็ตสาธารณะ
